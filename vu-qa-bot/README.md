# Генератор синтетического датасета ВУ

Размеченный тестовый датасет для замера precision/recall валидатора ВУ и регрессионного теста в CI.
Реализация ТЗ v2.3 (бот — одна команда `/me`; датасет и метрики — через CLI).

## Что это

Генератор производит **структурированные записи полей** (JSON), а не изображения документов.
Каждая запись без исключений помечена как синтетическая:

* `synthetic: true` — предикат `is_synthetic(rec)` истинен для всех записей;
* поля разметки `expected_valid` / `broken_rule` / `identity_source`, которых не существует в реальном потоке.

> С версии 2.1 серия формируется из **реального кода региона** (первые две цифры = код подразделения из поля 4c), поэтому признака синтетики внутри самих полей больше нет — он живёт только в метаданных.

Эти признаки — часть контракта датасета: по ним CI отличает тестовые записи от боевых.

## Установка

```bash
python3 -m venv .venv
./.venv/bin/pip install -r requirements.txt
```

## Переменные окружения (только для бота)

| Переменная | Обязательна | Назначение |
|---|---|---|
| `BOT_TOKEN` | да | токен от @BotFather |
| `ALLOWED_USERS` | да | `user_id` через запятую; **без неё бот не стартует** (выход с кодом 2) |

```bash
export BOT_TOKEN=123456:AA...
export ALLOWED_USERS=681094413,8962741939
./.venv/bin/python vu_qa_bot.py
```

Сообщения от пользователей вне списка игнорируются молча, без ответа.

## Команды бота

| Команда | Поведение |
|---|---|
| `/start`, `/help` | баннер, формат ввода, сохранённые данные |
| `/me` | показать сохранённое + клавиатуру подразделений |
| `/me ФАМИЛИЯ ИМЯ ОТЧЕСТВО ДД.ММ.ГГГГ МЕСТО РОЖДЕНИЯ` | единственная рабочая команда |

Дата служит разделителем: до неё — ФИО, после — место рождения (необязательно).
После выбора подразделения бот выдаёт запись с **неистёкшим сроком** (`valid_now`).

Битые записи, мутаторы, `.jsonl` и метрики — только через CLI.

Данные хранятся в `profiles.json` рядом с ботом, ключ — `user_id`; данные одного пользователя невидимы другим. Пол выводится из отчества (`-ОВНА/-ЕВНА/-ИЧНА` → жен., `-ОВИЧ/-ЕВИЧ/-ИЧ` → муж.), иначе — из окончания фамилии.

## CLI

```bash
# 500 валидных + 1100 битых, воспроизводимо
./.venv/bin/python vu_testdata.py --valid 500 --mutated 1100 --seed 7 -o dataset.jsonl

# из своих данных, подразделение — Москва (77) → серия 77XX
./.venv/bin/python vu_testdata.py --valid 10 \
    --identity "ЩЕРБАКОВ ДМИТРИЙ ВАЛЕНТИНОВИЧ 14.03.1988" --region 77 \
    --birthplace "Г. ВОРОНЕЖ" --valid-now
```

`--region` принимает код из справочника (85 кодов); неизвестный код — выход с кодом 2.
Без `--identity` подставляется служебный плейсхолдер `ТЕСТОВ ТЕСТ ТЕСТОВИЧ 01.01.1990`.

## CI

```bash
./.venv/bin/python eval_rules.py --valid 500 --mutated 1100   # код 0 при precision=recall=1.0
./.venv/bin/python test_vu.py                                 # критерии приёмки §9
```

`eval_rules.py` возвращает ненулевой код, если есть хоть один ложно-негатив (мутатор не сработал), ложно-положительный (валидную отбраковали) или запись, у которой `is_synthetic()` ложен.

## Правила валидатора

| Правило | Проверка |
|---|---|
| R01 | `translit(x_ru) == x_lat` для 4 пар полей |
| R02 | срок = выдача + ровно 10 лет |
| R03 | `back_number == "{series} {number}"` |
| R04 | замыкание зависимостей категорий |
| R05 | `back_table.keys() == set(categories)` |
| R06 | возраст на дату выдачи ≥ порога строжайшей категории |
| R07 | код региона подразделения из справочника (85 кодов) |
| R08 | только допустимый алфавит из 16 категорий |
| R09 | дата выдачи не в будущем |
| R10 | год в поле 14 ≤ года выдачи |
| R11 | дата открытия категории ≤ срока действия |

Валидатор проверяет **формальную консистентность** записи, а не действительность документа: истёкший срок сам по себе не делает запись `red`. Автопродление 2022–2025 (`effective_expiry`) учитывается отдельной функцией, общей для генератора и валидатора.
